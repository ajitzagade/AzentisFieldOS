## Intent

**Problem:** The 5 Help & Guides walkthroughs are text-only. The UX spines (EXPERIENCE.md "Guide screenshot pipeline" + DESIGN.md Guide-step annotation, 2026-09-06; approved mock `mockups/25-help-guide-annotated-screenshot.html`) commit to a real annotated screenshot per step — captured by a script, never hand-annotated — and nothing implements that.

**Approach:** A Playwright-driven capture run reuses the existing e2e harness (seeded `azentisfieldos_e2e` DB, servers on 3100/3101, auth fixtures) to drive the real app to each guide step's screen and screenshot it at a mobile and a desktop viewport, recording the target element's bounding box. A committed manifest maps guideId+stepIndex → image + ring rect per viewport. The guide page overlays a CSS-pulsing `accent-teal-700` ring (2px, 4px offset, ~2s pulse, `prefers-reduced-motion` honored) positioned by percentage over a plain lazy-loaded `<img>`; mobile vs desktop image selection is pure CSS by breakpoint. Steps without a capture fall back to today's text-only rendering.

## Boundaries & Constraints

**Always:** Capture against the e2e database/harness only — never dev or prod data. Capture signed in as the seeded Owner (sees all fields, incl. D7 pricing). Images and manifest are committed artifacts regenerated by one root script (`pnpm help:screens`), mirroring the `presentation:build` precedent. Ring is a DOM overlay on the page (animated), never baked into the PNG. Ring/animation styling comes from design tokens in `packages/ui` (AD-4); the pulse is the sanctioned ambient-loop exception (DESIGN.md Do's/Don'ts, 2026-09-06). Plain `<img loading="lazy">` (no next/image — repo convention). Selector strategy: `getByLabel` / `getByRole("combobox"|"button", {name})` — never `id` (useId is nondeterministic). A step with no capture entry renders exactly as today.

**Ask First:** Adding any new npm dependency (e.g. image tooling — target zero new deps beyond what exists); any change to seeded e2e fixtures that existing e2e specs rely on; capturing as Supervisor for any step.

**Never:** No hand-edited screenshots or manifest entries. No selector/capture data in `packages/shared` (capture plan lives with the e2e code; the shared content stays presentation-agnostic). No changes to guide step text or to the existing e2e specs/config beyond additive reuse. No horizontal overflow from images (max-width 100%).

## Design Notes

Ring overlay math: manifest stores `{x,y,w,h}` in CSS px at capture viewport plus the image's `{w,h}`; the component positions the ring div with `left/top/width/height` as percentages of image size, so it scales with responsive display width. Ring: `2px` border `accent-teal-700`, `4px` offset (inflate rect by 4px each side before converting to %), `~2s` opacity pulse per DESIGN.md.
